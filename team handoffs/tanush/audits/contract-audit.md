The all-operations transport test requests an assurance artifact and validates the frozen response (`tests/contracts/platform/test_transport_complete.py`, `getArtifact` call and `Transport.call`).

The old registration-only conformance test remains, but it is now supplemented by a real consumer test. The test explicitly records the JSON export schema conflict instead of concealing it.

## Open findings

1. **P1 — JSON passport export still violates the frozen 200 response schema (CR001).** The frozen `application/json` schema is `{"type":"string"}` (`architecture files/contracts/openapi.yaml:3157-3160`). The actual renderer emits a JSON object with `export_schema_version`, `manifest_sha256`, `canonical_manifest`, and `bundle`, returned unchanged by `src/analogforge/api/router.py:278-291`. The new transport test explicitly expects `ValidationError` on the parsed object (`tests/contracts/platform/test_transport_complete.py`, `Transport.call` special case), so its green result is *not* a pass of this response schema. CR001 requests the central contract correction; kit bytes remain unchanged pending merge owner action.
2. **P2 — Several reachable error statuses remain undeclared (CR001).** Fresh TestClient probes: unknown `/api/v1/configuration/scenarios/no-such-scenario` returns 404 `NOT_FOUND` while that operation declares only 200 (`router.py:186-190`); `/api/v1/display-layers?run_id=x` returns 422 `INPUT_INVALID` while that operation declares only 200 (`router.py:51-72`); a 262145-byte POST `/api/v1/missions` returns 413 `INPUT_TOO_LARGE`, which no frozen POST declares (`src/analogforge/api/security.py:20-30`). CR001 covers 404/422/413. The new test checks 404 for other object reads but does not cover these invalid parameter, unknown scenario, or oversize paths.
3. **Historical P2 — scientific claim rejection lost diagnostic issue codes; fixed above.** `ScientificClaimRejected` stored `issue_codes` (`src/analogforge/application/assurance.py:29-34`), but the earlier generic `PersistenceError` handler returned `details: {}`. A TestClient probe then returned 422 with empty details. The later specific mapping and actual HTTP regression are recorded in the latest validation above.

## Test limits and notes

- The new transport validator checks declared response headers, yet its `application/octet-stream` fallback can accept an unexpected Content-Type for that response; the actual artifact handler currently sends the declared type.
- It treats the JSON export mismatch as a documented expected failure and does not make the frozen schema pass. Its error coverage is representative, not exhaustive for every status of every operation.
- The new API group modules select operation IDs and delegate to the central `dispatch`; no duplicate handler logic was found. Four `/auth` routes are outside the frozen `/api/v1` group and excluded from its 43-operation count.
- `main.py` maps `SOURCE_UNAVAILABLE` and `IDENTITY_PROVIDER_UNAVAILABLE` to 503, `BUDGET_EXHAUSTED` to 429, revision/transition conflicts to 409, and its generic persistence/workflow fallbacks to 422. The historical claim issue-code loss above has been fixed.
