### New P2 — OIDC provider failures are not mapped to a safe API error

`adapters/identity/oidc.py:40-43,105-117` calls the issuer discovery, token and JWKS endpoints with `httpx` and raises for HTTP error status. `/auth/login` and `/auth/callback` (`api/routers/auth.py:58,76`) do not translate `httpx.HTTPError` or malformed issuer JSON, and `main.py:152-184` has no handler for them. A temporary issuer outage therefore becomes a generic 500 rather than a stable `503`/`AUTHENTICATION_UNAVAILABLE` envelope; the browser cannot distinguish retryable upstream failure from an application fault. Map upstream transport/status/JSON failures to a sanitized, retryable authentication error; keep the provider response body, URLs and secrets out of the envelope and logs. Add a real HTTP test.

## Findings

### P1 — Hosted authentication cannot establish a session

`src/analogforge/api/router.py:320-339` registers only the 43 frozen `/api/v1` GET/POST operations. `src/analogforge/main.py:184-187` includes only that router. There are no `/auth/login`, `/auth/callback`, `/auth/logout`, or `/auth/session` routes or any `set_cookie` call in `src/`. In OIDC mode, `src/analogforge/api/dependencies.py:29-35` requires pre-existing `af_session` and `af_workspace` cookies for every route, so a new user cannot sign in. Architecture 24 lines 7-11 and Tanush module spec line 106 require these routes outside the frozen scientific contract. The current identity unit tests exercise `OIDCClient` and `IdentityService` directly; they do not exercise HTTP sign-in/cookie attributes. Reproduction: inspect `create_app().routes` for paths beginning `/auth` (empty), then request `/api/v1/capabilities` in OIDC mode without externally manufactured cookies (401). Add the four routes; callback must verify OIDC state/code, resolve existing workspace membership, create server-side session, and set Secure/HttpOnly/SameSite=Lax cookies. Test the full browser-facing flow with a fake issuer.

### P2 — Untrusted evidence `source_uri` accepts active or non-HTTPS schemes

`src/analogforge/application/registrar.py:214-217` rejects credentials, query and fragment but does not require an approved HTTPS scheme or origin. `javascript:alert(1)` and `file:///etc/passwd` have none of those rejected components and can be persisted into a public `EvidenceRecord` at line 255. The frozen ports type the URI as an unconstrained string (`ports/science.py:161`, `ports/domain_models.py:192`). This is a stored unsafe link value, not a confirmed script execution: exploitation depends on a UI or renderer using it as a hyperlink. Reproduction: `urllib.parse.urlsplit('javascript:alert(1)')` yields empty query, username, password and fragment, so it passes the registrar's predicate. Require HTTPS plus source host policy, or store non-HTTP provenance as plain text with an explicit non-clickable type. Add registrar tests for `javascript:`, `file:`, scheme-relative, credentials and signed URL cases.
