# Frontend dependency security upgrade (2026-11-13)

Recorded in its own file so it merges independently of the shared decision log.

## D-2026-11-13-DEPS: Frontend dependency security upgrade of the release candidate
`pnpm audit` on the merged candidate reported 15 advisories in production dependencies (1 critical, 7 high) and 17 more in tooling. None of the production ones was reachable in this application (MapLibre's `Popup.setHTML` sanitiser bypass: the app has no popups or HTML sinks; React Router's server-rendering, RSC and framework-mode issues: the app is a client-side `BrowserRouter`; Ajv's `$data` ReDoS: not used), but patched releases exist for all of them, so they were upgraded and proved rather than argued away: `react-router-dom` 7.9.6 to 7.18.5, `ajv` 8.17.1 to 8.20.0, `maplibre-gl` 5.12.0 to 6.18.0, `vite` 7.2.2 to 7.3.8, `vitest` 3.2.4 to 4.1.12. Production audit: no known vulnerabilities. Tooling audit: 1 moderate remains (`minimatch` inside `typescript-eslint`, which needs a major bump of the lint toolchain and is never shipped).
**MapLibre 6 needed two changes, and only one of them was visible to tests.**
- It no longer has a default export (`import maplibregl from` became `import * as maplibregl from`). The production build failed loudly.
- It loads its web worker from a separate file whose URL it computes at run time, which a bundler cannot see. The production build **succeeded but emitted no worker**, so the shipped map would have failed to start; in dev the pre-bundled dependency cache also lacks it. The dev-server browser tests passed; only the visual audit's console and network check (C12) caught it in dev, and only a run against the production build proves the shipped case. `EarthMap` now imports the worker file as an asset (`?url`) and registers it with `setWorkerUrl`, which makes the bundler emit and serve it. Verified on the production build served against the real backend: worker `200`, canvas drawn, no console errors, no failed requests.
- The camera unit test mocked the library without `setWorkerUrl` and failed once the module registered the worker; the mock now provides it.
**Licence notices.** `thirdParty.ts` is hand-maintained. It lists every runtime dependency except `ajv` and `ajv-formats`, an omission that predates this change; both (MIT) are added, and the three upgraded versions are updated.
**Verified:** typecheck, lint, 134 unit tests, contract tests, build, generated client unchanged, kit verify, UI scan and purity; all 40 mock browser tests and the 501-check visual audit pass after the worker fix.
