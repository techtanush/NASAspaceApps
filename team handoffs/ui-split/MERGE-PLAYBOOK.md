# Later merge playbook — preserve independent ownership

Shared immutable seed: `ui-split-base-20261114`. All inherited BETTERUI code and these handoffs are already in both contributor branches. main remains the stable pre-UI release until new work passes integration.

1. Contributor compares `rtk git diff --name-only ui-split-base-20261114...HEAD` against OWNERSHIP.json. Include only their own new work; inherited seed files are not new cross-owner changes. Record exact gate source/head and remaining limitations in their folder's STATUS. Backend contract changes require the shared architecture35 process.
2. Fetch latest main and both contributor branches; inspect unexpected new commits, clean state and open work before updating. Do not overwrite another contributor or force push. Do not use `-X ours`, `-X theirs` or automatic deletion of conflicts.
3. Create an isolated integration worktree/branch from current origin/main. Merge `origin/tanush/platform-agents-integration` (contract/data delivery), then `origin/aradhya/frontend-experience` (frontend). Normal merges share the same seed once. If a tiny contract slice was integrated earlier, preserve its ancestry rather than copying generated files manually.
4. Exclusive frontend src vs backend Python/versioned public data should merge without file collisions. Shared catalog/schema mismatch is a version compatibility defect, not a text conflict to paper over. Resolve shared docs by preserving both required scientific and product behavior. Existing frozen kit files require byte-verification after any permitted additive materialization.
5. Install locked dependencies, verify kit/client generation, run make check on the actual merged tree, all old plus new browser journeys against isolated real backend, visual/accessibility/print audits and all mutation gates. Run new regional alignment/security/data tests as well. No credential needed for default synthetic checks.
6. Separately rehearse with actual validated NASA data, no test hooks. Select individual adjacent Flagstaff windows, Earth detail and Gale target detail; verify mask, coordinates, native/effective/support labels, no stale layers, FAIL/UNKNOWN/LIMITED/no-rover truth and immutable exports. Missing additional geography is an explicit supported-data limitation, not a fabricated demo location.
7. Record source hashes, branch heads, command/count receipts and screenshots. Freeze code during gates; after any implementation fix rerun affected gates and required merged final checks. A green main1721844 or the 144-test planning baseline does not certify the new merged UI.
8. Commit/push the integration candidate and open a ready PR describing final behavior and limitations. Merge only the verified candidate through normal GitHub workflow, then confirm remote main's tree equals the tested tree. Keep private assets/keys/DB and transient captures ignored.

Both contributors can finish their owned modules against schema fixtures independently. Cross-branch work is limited to versioned additive seam changes and the final integration; neither should wait to polish unrelated files or build the other's layer.
