# Integrated operations handoff

15 November 2026. This describes the integration checkout's behavior and operating boundaries. It does **not** certify a completed current LIVE investigation or a final release gate. Preserve failed/blocked runs and their receipts; historical results from another checkout do not establish this checkout's result.

## Start with an isolated server environment

Run commands below from `analogforge/`, with the intended private `DATABASE_URL`, `DATA_ROOT`, `CONFIG_DIR`, ports and exact `ALLOWED_ORIGINS` already selected. Keep credentials server-side in ignored configuration; never use `VITE_*` variables for secrets. Do not copy live credentials into synthetic/browser-test profiles. Actual LIVE work requires real science/renderer implementations and disabled fake-provider/test-harness hooks.

For an already prepared database and installed dependencies, the source's development supervisor starts API, worker and real-backend web together:

```bash
rtk proxy env OPENAI_MODEL=gpt-5.4-mini AF_SCIENCE_IMPL=real AF_RENDERER_IMPL=real uv run --locked python scripts/dev_services.py
```

This is an explicit process-only model choice, inherited by API and worker. `gpt-5.4-mini` was selected from availability already present in the existing account; it is not an app-wide default or a capacity guarantee. Account limits remain external. **No billing, quota or account settings were changed.** Restart both API and worker after changing their environment or source. The normal `rtk make dev` additionally bootstraps, migrates, seeds synthetic fixtures and performs synthetic preflight; it is not a live-data readiness certificate.

Optional `OPENAI_MIN_REQUEST_INTERVAL_SECONDS` is finite and bounded to 0–60, default 0. A shared process-local reservation spaces primary requests, including failed attempts. It is software pacing, not a token-aware distributed limiter or an account quota change. The current local rehearsal uses 60 seconds and the explicit fallback order described below. Earlier Groq 120b schema checks succeeded where 20b returned `output_parse_failed`. Diagnostics do not establish a completed investigation or guarantee against rate limiting. No token/request/run ceilings or strict evidence gates were increased.

## Surface imagery and camera controls

The globe is an overview. Selected Earth sites open a regional satellite map; close globe zoom transitions to that selected site's detailed view. Eligible CONUS sites default to USGS Imagery Only aerial context, with EOX Sentinel-2 available as the global alternative. Near Flagstaff the delivered USGS level 16 tiles provide approximately 1.95 m/pixel display sampling; the camera stops at its corresponding level 15. The EOX 2016/2017 mosaic stops at approximately 15.6 m/pixel there. Both are historical visual context, with dates varying by source, rather than live surveillance or obstacle measurements. The native Comet check reached a 100 m map scale with roads and tree patterns visible, then zoomed out and fitted the original server AOI again. The blue outline is never resized by a camera gesture. Satellite view temporarily hides measured overlays; Measured terrain restores their exact selection and opacity.

Mars and Moon now have actual orbital tile views, separate from measured terrain. NASA Trek's published resource URL supplies the preliminary uncontrolled Caltech CTX beta01 Mars mosaic through Esri; lunar imagery is LRO WAC global v2. Body-specific spherical degree tile matrices, coordinate frames, source limits and attribution are documented in [planetary sources](../../analogforge/apps/web/src/maps/PlanetaryBasemap.sources.md) and [Earth sources](../../analogforge/apps/web/src/maps/EarthImagery.sources.md). Missing/failed imagery is explicit. Image sampling never changes numerical analysis resolution.

Zoom, pan and recenter change only the camera. The outlined region always uses the accepted target or server candidate AOI; no zoom gesture edits scientific bounds. Numeric selection tools remain under a disclosure. Planetary zoom stops at each source's actual tile ceiling; initial zoom-out responds immediately even on a smaller-than-resolution target. Earth retains its native map camera bounds because applying a full-world `maxBounds` caused a real MapLibre 6 transform failure. Tiles remain source-bounded and requests remain limited and cancellable; normal canceled tiles do not mark the source unavailable.

## Durable investigation activity

`GET /api/v1/runs/{run_id}/activity?limit=25&cursor=...` is an additive, authenticated, workspace/run-scoped, read-only endpoint with `Cache-Control: no-store`. It is outside the frozen 43-operation schema. `limit` is 1–100; the opaque cursor is scoped to workspace/run. Pages are in ascending event sequence and return `items`, nullable `next_cursor`, and `last_event_seq`.

Each item has stable `id = run_id:seq`, `run_id`, `seq`, `event_type`, `created_at`, `state`, `status`, `summary`, and nullable `failure_code`, `task_kind`, `role`, `candidate_id`, `candidate_name`, `requirement_id`, `invocation_id`, `tool_receipt_id`, plus `evidence_ids`. Statuses are `RUNNING`, `COMPLETED`, `BLOCKED`, `FAILED`, `CANCELLED`, or `INFO`. On recognized failed/blocked terminal records, `failure_code` comes only from an allowlisted identifier in the persisted event's `payload.code`; the summary adds its fixed human explanation. Unknown, absent or unsafe codes remain null. Started, successful and cancelled records cannot acquire a failure code from other run/receipt metadata. A failed background job does not relabel an already completed investigation.

Summaries project actual committed events and authorized records. Workers commit start records before scientific/provider execution; completion or failure is a separate transition. A historical “Started” record does not mean the operation is still running: correlate terminal records by invocation and consult current run state. Reload/resync reads the durable history; SSE watermark changes trigger UI refresh. The UI displays at most the first 2,000 records with a limit notice; endpoint pagination remains available. No scripted scenario outcomes, estimated percentages, raw code, prompts or hidden reasoning are progress records.

Role completion events carry `role_result_id` and `evidence_count` rather than repeating a growing global evidence list inside the 16 KiB event envelope. The full canonical role result retains every evidence reference. Activity items additionally return nullable `role_result_id`, `evidence_count`, and `evidence_ids_truncated`; `evidence_ids` displays at most 128 unique authorized references. Counts come from the scoped stored records, not an unverified count in event text. A shortened display is explicitly marked and does not remove evidence from the result.

`review_concerns` is an additive array, empty unless a blocked completion links to an admitted blocked role result with matching run, invocation, role and mode. At most eight WARNING/BLOCKING concerns expose only sanitized plain text (800 characters), a truncation flag, severity and a label from the pinned contract. Foreign requirement labels, links, credential text, source payloads and provider reasoning are not copied. The terminal notice shows these as reviewer concerns alongside unchanged measured results; it does not treat a concern as a new scientific verdict. Older deployments may omit the field. An unavailable/unauthorized activity response exposes no retained concern.

Source: [activity projection](../../analogforge/src/analogforge/application/activity.py), [router](../../analogforge/src/analogforge/api/routers/runs.py), [UI consumer](../../analogforge/apps/web/src/features/missionControl/RunActivity.tsx).

## Per-location current evidence PDF

`GET /api/v1/runs/{run_id}/candidates/{candidate_id}/evidence-brief.pdf` downloads an actual PDF attachment for the exact authorized location, including when the run is active, blocked or failed and has no published passport. The endpoint is separate from the frozen core and does not require the visualization flag. It shows saved mission/rover revision numbers and hashes, target/site bounds, regional search scope, accepted priorities/co-location groups, committed criterion results and compatible measurements, registered terrain graphs/views, attempt references, gaps and source limitations. Missing qualifications remain Unknown; existing FAIL/GAP/UNKNOWN are preserved. Terminal cause text comes only from an allowlisted persisted event code, never a provider response.

This is labelled **Current evidence brief**, an unassured snapshot rather than an Analog Passport. Each location's PDF starts with an executive summary, followed by a simplified overview with measured benchmark graphs, then complete technical details and terminology. It changes no published passport, acquires no source data and calls no model or scientific operation. Rendering is offline and bounded, with pinned ReportLab in `extra-tanush`, embedded local fonts, one child per API process, private/no-store download semantics and explicit omission notices for oversized display views. The response includes the PDF digest, snapshot digest and observed run revision. See the [PDF extension contract](../../analogforge/docs/site-evidence-brief.v1.md) for exact authorization, limits and errors. Synthetic PDF QA establishes rendering behavior only; it does not certify a completed genuine NASA investigation.

Results open location by location in the regional map, with the assigned purpose, accepted benchmarks and scoped measurement graphs. Simplified / Technical details controls change disclosure depth after research reaches review or a terminal boundary; they do not change results or research commands. The PDF always retains all sections. Active research has one common durable work log. Review pauses use a plain-language notice and recovery link; exact status codes remain in a technical disclosure. Failures and missing results are not removed or relabelled as success. The rounded light sidebar uses the existing bounded glass surfaces and Motion with reduced-motion support; measurement wells remain solid and readable.

## Optional stored weather/context

Meteomatics uses those Basic-auth credentials, not a separate API-key field. `EARTHDATA_TOKEN` is a separate acquisition credential, not a weather login. Visualization routes separately require `ANALOGFORGE_VISUALIZATION=1`.

A leased LIVE worker captures context once after detailed Earth candidate analysis. Synthetic/replay/test-harness work never performs this acquisition. Limits are six candidate AOI midpoints, eight HTTP calls and 30 seconds shared across acquisition/verification/publication. Interrupted attempts remain unavailable rather than silently querying again.

`GET /api/v1/runs/{run_id}/environment` is authenticated, workspace-scoped, `no-store`, and **stored-only**: viewing or reloading never calls a weather provider. `schema_version` is `environment.v1`; common fields include `run_id`, `mode`, `status` (`CAPTURED` or `UNKNOWN`), `reason_code`, `earth_candidates`, `nasa_reference`, nullable `snapshot_sha256`, `limitations`, `qualification_supported: false`, and `operating_limits: []`. Captured snapshots also carry immutable input identities, capture time, omitted candidate IDs and budget metadata. `CAPTURED` does not mean every source item succeeded. Disabled/missing credentials, absent/interrupted capture, unsupported geometry, source/storage failures and exhausted budgets remain explicit reasons; corrupted stored context fails closed.

Earth samples describe one point and a declared UTC window. NASA REMS is historical Curiosity rover-point reference context; selected Mars AOI applicability remains `UNKNOWN`. Neither establishes current/global Mars weather, climatic analogy, operating safety limits, qualification evidence or candidate ranking. ## Identity and model behavior

`AUTH_MODE=local` requires a loopback API host. `GET /auth/session` automatically returns the fixed local `OWNER` identity, `auth_mode: local` and null CSRF token. The UI labels this “Local workspace / Owner”; there is no meaningful local account sign-in/out gate. Local `/auth/login` is disabled; clearing cookies does not remove automatic local identity.

Configured OIDC uses `AUTH_MODE=oidc`, HTTPS `PUBLIC_BASE_URL`, `OIDC_ISSUER_URL`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, a `SESSION_SECRET` of at least 32 characters, exact origins and administrator-provisioned workspace membership. Backend login is `GET /auth/login?workspace_id=<uuid>`, followed by `/auth/callback`; logout is `POST /auth/logout` with matching Origin and `X-CSRF-Token`. Secure cookies/session revocation are real backend behavior. Current Mission Control supplies an identity badge, not a complete OIDC account-management screen. See [auth routes](../../analogforge/src/analogforge/api/routers/auth.py).

Live models require `OPENAI_API_KEY` and explicit `OPENAI_MODEL`. An optional ordered `MODEL_FALLBACK_ORDER` supports Groq, OpenRouter, Anthropic, SambaNova, NVIDIA and Gemini through independently authenticated text transports. Keys alone enable nothing. Legacy Groq-only opt-in remains supported when the order is omitted. The R72 local rehearsal explicitly selects primary `gpt-6.1-sol`, `OPENAI_REASONING_EFFORT=low`, a 2,048-token total output cap and 40-second minimum request spacing and fallback order `["nvidia"]` with `nvidia/nemotron-3.5-super-vl-120b-a12b`. Groq remains implemented but is disabled in this local chain after full-run tool/quota errors. Only HTTP 429 permits advancing; authentication/schema failures do not select another provider. Fallback output defaults to 1,024 tokens; explicit `NVIDIA_MAX_OUTPUT_TOKENS` is bounded to 256–4,096 (current local rehearsal: 2,048), without raising other provider caps or any request ceiling. Primary role requests default to 4,096 and can be lowered with `OPENAI_MAX_OUTPUT_TOKENS` (256–4,096); the R78 rehearsal uses 2,048 total tokens, including reasoning. Every actual attempt/correction is charged within the six-per-invocation/40-per-run ceilings. Exactly one serial tool call, canonical schemas and authorized evidence remain enforced. Incomplete/repeated invalid output stays `MODEL_OUTPUT_INVALID`; oversized input is `RESOURCE_LIMIT`; rate limits remain provider failures. No partial proposal is accepted to make a run appear successful. Other providers remain disabled locally unless capability and account access are separately confirmed. See the [fallback contract and bounded diagnostic receipts](../../analogforge/docs/text-provider-fallbacks.v1.md), [client](../../analogforge/src/analogforge/adapters/openai/client.py) and [provider loop](../../analogforge/src/analogforge/agents/runtime/openai_provider.py).

## Regional terrain, coverage and benchmark limits

The acquired local sources are genuine MOLA MEGDR (`mola-gale-v3`) and NASADEM HGT (`nasadem-flagstaff-v002`) regional crops. Their source identities, native posting, frame preparation, bounds, height references and checksums are described in the [acquisition runbook](../../analogforge/LOCAL-LIVE-RUNBOOK.md). The isolated regional profile uses 500 m analysis/comparison support and 12 km candidate windows; this does not turn native posting into effective measurement resolution. The operator-reviewed demonstration criterion is not a NASA-calibrated suitability threshold. Terrain crops supply neither mineral/thermal equivalence nor physical rover validation. An unreviewed reference set establishes no historical novelty.

**Current real-data scope is regional:** Gale target terrain and a Flagstaff Earth raster crop. Screening enumerates supported windows from the run's locked sources. It does not query a global Planetary Computer elevation catalog or establish globally best Earth locations. Current Moon numeric coverage remains unavailable; orbital lunar photographs do not fill that gap. Candidate ordering and benchmark-specific portfolio assignment adapt to actual target/requirements/priorities/rover constraints within this scope. Real-raster metamorphic regressions cover these changes; unsupported features remain UNKNOWN. Tour/report text states the screened search scope.

Global globe imagery is `VISUAL_CONTEXT_ONLY`; attractive coverage on a globe does not provide quantitative regional evidence. With visualization enabled, `GET /api/v1/visualization/coverage` takes `body`, `bbox=w,s,e,n`, `scenario_config_id` and optional `dataset_lock_id`. Its `COVERED/PARTIAL/NONE/UNKNOWN` result describes a validated locked **footprint**, not valid-cell completeness or mission PASS. Missing/stale preparation stays `UNKNOWN`; polar/dateline-spanning boxes are unsupported. Prepare metadata explicitly, outside GET:

```bash
rtk proxy uv run --locked analogforge visualization prepare-coverage --dataset-lock <selected-lock-id>
```

`GET /api/v1/runs/{run_id}/visualization/candidates/{candidate_id}/benchmarks` reads accepted requirements and pinned qualifications. Numeric values require the exact registered comparison artifact, accepted criterion, candidate lineage, units/support and any necessary candidate-scoped verifier ancestry. Otherwise the value remains null/Unknown. This endpoint computes no new score, margin or measurement. GAP/UNKNOWN and nonnumeric criteria remain visible; without a rover, compatibility/verification remain unassessed/not run as applicable. The visualization schema is available at `/api/v1/visualization/openapi.json`.

An algorithm/configuration version or support change requires a **new run**, with the reviewed contract and intended source-policy lock; do not retry an old run into a different pinned algorithm configuration. Rebuild coverage metadata when configuration/source identities change. Keep original datasets/locks immutable and use fresh dataset/policy IDs for changed inputs. Acquisition/lock/bind command syntax is documented in the runbook and implemented in [CLI](../../analogforge/src/analogforge/cli.py). This handoff adds no new test, provider or final-green claim.

## Final review repairs

The optional font downloads no longer block authenticated workspace rendering. Each development server has an isolated Vite cache by preview/API mode and port, so simultaneous live/browser servers cannot replace each other's optimized modules. A real-backend browser test holds font requests open while checking both initial body choices remain usable.

The private role wire format uses `~~` to escape literal tildes, preserves ordinary approximations such as `~0.5 km`, and still rejects unknown reserved aliases. Provider summaries are requested concisely before generation, with the original canonical validation retained. Each role receives the exact accepted contract in its initial context; homogeneous requirement rows are represented losslessly and the canonical read remains available. The last remaining run request is reserved for an assessment rather than another read, without raising the six/40-request limits. A false publication-readiness proposal now requires a concrete issue or a known unresolved issue; invalid empty holds get the existing correction and never force publication. Justified objections still hold the report. See the text-provider contract for exact bounds.

The root [Sponsor Integrations](../../Sponsor%20Integrations.md) document covers the ten offer cards read in native Comet. It distinguishes connected scientific/context inputs from future infrastructure, team tools and the unregistered domain.


Target/Scout reviews receive the complete registered target profile and a receipt-bound coordinate context. The latter matches a successful characterization operation to its actual `characterize_target` receipt using workspace, run, mode, AOI and evidence identity. Source CRS and height-reference metadata comes only from the matching successful `fetch_dataset` ingestion manifest. A contract-inspection receipt cannot masquerade as geometry validation. Missing validation is nullable and remains unready; the original operator AOI is unchanged. These are provenance/availability facts, not a new scientific PASS.
