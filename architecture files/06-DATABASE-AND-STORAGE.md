# Database and artifact storage

Use PostgreSQL 16/PostGIS 3.4 for structured records and Earth spatial indexing. Store source products, processed rasters, route telemetry, and export files in content-addressed storage. Every persisted scientific result must be reproducible from its input references, algorithm version, and parameters.

## Required tables

All user-owned tables carry `workspace_id UUID NOT NULL`; foreign keys include workspace_id or are validated by scoped repositories. Timestamps are timestamptz. Use JSONB for versioned document bodies, not as a substitute for searchable identity/status/index columns.

## Database enforcement

Apply enum/check constraints for states and percentages. Composite workspace foreign keys prevent cross-workspace joins even when a programming error passes the wrong ID. Application authorization is mandatory; enable row-level security in hosted mode using transaction-local workspace/user settings and a non-superuser application role. Worker service role must also scope operations; a global worker can claim a job but its subsequent domain writes use the job workspace.

Protect immutable tables with update/delete denial to ordinary app roles after commit. Corrections create superseding records. Garbage collection removes unreferenced blobs only after a 24-hour grace period; deleting a workspace is an explicit administrative action, not a worker tool.

## Atomic result publication

1. Stream output to `DATA_ROOT/tmp/<job-id>/<random>.part`, enforce byte budget, flush and fsync.
2. Compute SHA-256, determine server-controlled media type, then atomically move into `blobs/<first-two-hex>/<full-sha256>` on the same filesystem.
3. In one DB transaction verify the worker still owns the lease token, insert blob metadata/evidence/receipt, update run revision, increment event sequence, and insert event.
4. Commit. If the transaction fails the blob is an unreferenced orphan eligible for later GC; no record may reference an incomplete file.

For object storage later, upload under content hash, verify HEAD/checksum, then commit metadata; lifecycle rules handle unreferenced uploads. Never let a user supply a filesystem path or storage bucket key.

## Planetary data

Planetary AOIs/CRS metadata live in typed JSON plus body-specific raster artifacts, not Earth SRID4326. PDS labels, projection WKT, longitude convention, and vertical reference are retained. An Earth spatial query cannot accidentally interpret a Mars longitude as an Earth candidate.

## Migrations

Migration order: extensions and identity; mission/rover revisions; runs/jobs/events/idempotency; storage/evidence/lineage; candidates/qualification/critique; tests/results/portfolios/passports; RLS/immutability/indexes. Test each upgrade on a new database and a seeded previous schema. Use expand/migrate/contract changes for deployed environments. Never auto-drop tables to solve a migration conflict.

## Acceptance

Cross-workspace reads and writes fail; an expired worker cannot commit; a duplicate command returns the original result; source hash changes invalidate derived caches; a crash between blob move and DB commit leaves only a recoverable orphan; backup restoration recovers both rows and all referenced blobs.

## Scientific assurance persistence

Include non-null passports.assurance_evidence_id referencing evidence in the initial passport migration; enforce same workspace/run/mode and presence in document_json.evidence_ids at application commit, with composite foreign keys/constraints where supported. Reports are immutable content-addressed DERIVED artifacts using existing tables, not mutable flags. Atomically commit audited conclusions, audit reference, passport manifest and event under current lease/revision fencing. A rejected proposal retains diagnostic evidence but creates no final passport. Preserve old reports on recomputation. See [33](33-SCIENTIFIC-CREDIBILITY-AND-CLAIM-GATES.md).
