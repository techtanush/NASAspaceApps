# Ayan — module specification

This is the file-by-file contract for your branch. It tells you *what each module must do and how it is judged*, not how to code it. Types come from the kit (`analogforge.ports.*`); semantics come from architecture 08–13, 29, 33, 35, 36, 40. Where this file is more specific than those, this file wins for your branch.

## 1. Global conventions (apply to every module)

* **Units/identity:** SI; degrees; Wh; percentages only in `*_pct`; unknown ⇒ `None`. Candidate identity = `window_id` string; platform UUIDs never enter pure code.
* **Distances:** route distance and exposure distance are **horizontal (planimetric) metres**; energy uses modeled surface length `d_s = sqrt(d_xy² + dz²)`; `dz` = difference of the two node cell-centre elevations (no interpolation).
* **Slope:** per-cell surface slope from the 3×3 least-squares plane in metric coordinates (architecture 10 §4); cells lacking full valid 3×3 support are **invalid** (never zero). Edge hazard slope = **max** cell surface slope over cells whose intersection length with the edge segment is > 1e-9 m.
* **Bands:** `[lo, hi)`; `[lo, hi]` only when `ExposureSpec.upper_inclusive` (final capped band).
* **Determinism:** same request ⇒ same payload and artifact bytes (excluding `elapsed_ms`). Seeds from `ScienceOptions.seed`; sorted iteration; stable tie-breaks. No wall-clock, no randomness without a recorded seed, no dict-order dependence.
* **Cancellation:** `context.check_cancelled()` at least every 250 ms of CPU work and each outer-loop iteration; never swallow `ScienceCancelled`/`ScienceDeadlineExceeded`.
* **Honesty:** `BLOCKED` (no payload) with a `ScienceIssue` when data/coverage/CRS/policy/capability is missing; `LIMITED` (payload + issues) when valid but partial; `FAILED` only for an unexpected engine error. Never raise for expected data problems.
* **Provenance of every evidence draft:** `parameters_sha256 = canonical_sha256({operation, algorithm_id, algorithm_version, parameters, input hashes, seed, algorithm_config_sha256})` via `ports.hashing`; `parent_*` lists every consulted input; synthetic sources name `SYNTHETIC_*` product ids and have `source_uri=None`.
* **Algorithm ids and UI-readable artifacts:** every payload-bearing operation emits an evidence draft with `algorithm_id = catalog.ALGORITHM_IDS[...]` whose artifact is the payload serialized with `ports.hashing.canonical_json_bytes` (`application/json`); `ANALYZE_CANDIDATE` additionally emits the `analysis-summary` child; `VERIFY_ROUTE` additionally emits `route-telemetry`. Architecture 35 §5b is binding. Tests assert each operation's evidence ids and that the artifact bytes parse back into the payload model.
* **No environment, no globals:** no `os.environ`; configuration only from parsed `config/*.yaml` loaded once into an immutable object keyed by `algorithm_config_sha256`.

## 3. Shared formats

**ANALYSIS_GRID artifact** (`media_type = application/x-npz`, role `ANALYSIS_GRID`): a ZIP container written with **fixed member timestamps (1980-01-01), sorted member names, stored (uncompressed)** so bytes are deterministic. Members (all `.npy`): `elevation_m` (float64, NaN-free; invalid cells hold 0 with `valid=false`), `valid` (bool: has full 3×3 support and is not nodata), `land` (bool; false for water), `slope_deg` (float64, defined where `valid`), `aspect_deg` (float64, NaN allowed only here), `quality` (uint8), plus `meta.json` (UTF-8 JSON: `cell_size_m, width, height, origin_x_m, origin_y_m, crs_wkt, body, source_evidence_ids, algorithm_id, algorithm_version, parameters_sha256`). `GridSpec.analysis_grid_sha256` is the SHA-256 of these bytes. A reader helper (`raster/store.py`) is the only code that parses it; the verifier uses the same reader but not the solver's graph.

**Metric ids** (`MeasuredMetric.metric_id`; quantity kinds in parentheses):

| id | meaning |
| --- | --- |
| `valid_fraction` (DERIVED) | valid land area / window area |
| `slope_area_fraction:<lo>-<hi>` (DERIVED) | fraction of valid land area with surface slope in `[lo,hi)`, e.g. `slope_area_fraction:12-18` |
| `surface_slope_deg:p05`/`:p50`/`:p95`/`:mean`/`:max` (DERIVED) | area-weighted statistics |
| `detrended_rms_height_m@<window_m>`, `robust_relief_m@<window_m>` (DERIVED) | per architecture 10 §5 with the physical window in the id |
| `slope_w1_deg` (DERIVED) | Wasserstein-1 distance of binned slope distributions, degrees |
| `min_temperature_k` (MEASURED), `mineral_valid_fraction` (DERIVED) | optional layers |
| `route_distance_m`, `route_duration_s` (DERIVED) | verified route |
| `unique_exposure_m:<requirement_id>`, `traversed_exposure_m:<requirement_id>` (DERIVED) | exposure per requirement |
| `max_surface_slope_deg` (DERIVED), `tasks_completed` (DERIVED) | route |
| `energy_nominal_wh`, `energy_conservative_wh`, `reserve_pct` (ASSUMED when `calibration_status=ASSUMED`, else DERIVED) | energy model results; `reserve_pct` may be negative |

Slope-histogram edges: `[0,2,5,8,12,15,18,25,35,90]`; Wasserstein-1 uses bin centres `1, 3.5, 6.5, 10, 13.5, 16.5, 21.5, 30, 62.5` (architecture 10 §6) at the **common support** (`max(native supports)`; coarsening by **area averaging**, never interpolation).

**`config/algorithms.yaml`** (strict, versioned; hashed): `algorithm_lock` (id→version for every algorithm id you emit), `measurement_specs` (`terrain-target-v1`, `terrain-earth-v1`: derivative window 3, comparison support rules, roughness windows 3/5/9 cells), `observable_policies` (one entry for **every** value of `catalog.OBSERVABLE_POLICY_BY_OBSERVABLE`: `quantity`, `units`, `valid_bodies`, `support_rule`, `coverage_denominator`, `min_valid_fraction` (0.80), `temporal_support`, `proxy_policy`, `decision_rule`, `tolerance`, `applicable_gates`), `grid` (`cell_size_m: 60`, `window_cells: 64`, `target_support_m` rules), `route_search` (`max_expansions: 200000`, `max_seconds: 30`, `max_labels_per_node: 32`, `max_edge_traversals: 2`), `energy_defaults` (the `earth-simple-v1` values of architecture 12 §5 as *proposals*), `design_defaults` (`max_route_m: 8000`, `task_dwell_s: 60`), `thresholds`, `fixtures` (generator ids, versions, seed `20261105`).

## 4. Operations

For each operation: **Inputs → required behavior → outputs (payload / evidence drafts / artifacts) → BLOCKED/LIMITED conditions.** Evidence `parent_*` = every input evidence consulted. Unless stated, evidence `kind=DERIVED`.

### 4.1 `INGEST_LOCAL_DATASET`
Validate `manifest` (strict) against the files at `context.local_dataset_root(dataset_id)`. Run **every** `check_id` of architecture 36 §4 in order, never short-circuiting (so the operator sees all failures). Detect HTML pages by content. Open with rasterio/GDAL (HGT, GTiff, COG, PDS/PDS4, netCDF with `variable`, AAIGrid); archives: reject traversal, symlinks, nested archives, expansion > 20×. Apply scale/offset **once** and record exactly which side applied it. For `RADIUS`, relative height = value − `reference_radius_m`, once. Determine `usable_for_quantitative_claims` per architecture 36 §4. Output `IngestLocalDatasetPayload` with all checks. Evidence: one `SOURCE` draft (no artifact bytes; `parameters_sha256` includes the manifest hash and every file hash; `dataset_product_id` from the manifest, or `SYNTHETIC_<dataset_id>` when synthetic). `BLOCKED` only if the directory/manifest cannot be read; failed checks are a **successful** computation (`SUCCEEDED`) with `usable_for_quantitative_claims=False` and the failing checks listed (the CLI exits non-zero from the checks).

### 4.2 `RESOLVE_COVERAGE`
For `adapter_id` in {`local_dataset`, `synthetic_practice`}: intersect the AOI with the registered datasets/fixtures of the right role and return `CoverageSelection`s with `coverage_fraction` and `access_state`. For network adapters (`earth_nasadem_hgt_v001`, `mars_mola_megdr`, `moon_lola_gdr`, `earth_emit_l2bmin_v001`, `moon_diviner_derived`, `earth_user_survey`): in `synthetic`/`replay` return `BLOCKED` (`UNSUPPORTED_PRODUCT`, "network adapters are unavailable in this mode"); in `live` use `context.http_client()` (CMR/PDS index) with deterministic sort and cap; missing credential ⇒ `access_state=AUTH_REQUIRED`; no overlap ⇒ `NO_COVERAGE` (a valid result). Never invent product ids.

### 4.3 `FETCH_SOURCE`
`live` only (network adapters) — stream to scratch with timeouts, byte limits, redirect validation (no auth across hosts), checksum compare when the provider supplies one, HTML-login detection, archive safety; returns `AcquiredAsset`s (`validation_status`), SOURCE evidence per asset (artifact = `SOURCE_BYTES`). In other modes `BLOCKED`. Cover with mocked HTTP only.

### 4.4 `CHARACTERIZE_TARGET`
Resolve the source (`SYNTHETIC_FIXTURE` generator, `LOCAL_DATASET` via the dataset root, or `ADAPTER_EVIDENCE`), crop to the target AOI **in the body's own projection** (polar stereographic wedges and longitude wrap handled by densified-boundary transform; never Earth CRS), normalize to elevation metres (radius→height once), aggregate to the measurement spec's comparison support (default: the native posting; the practice Mars/Moon targets compare at 480 m / 960 m native, with Earth aggregated to **480 m** for the Mars scenario and **960 m** for the Moon scenario — the common support is `max(target native, requested)` recorded in the evidence), compute metrics and the slope histogram (area-weighted), valid fraction, optional thermal metric when a `LUNAR_THERMAL` dataset is bound (`min_temperature_k`). Evidence: `SOURCE` (fixture/local) → `DERIVED` profile (artifact `DERIVED_JSON` with histogram+metrics and the ANALYSIS_GRID of the target at comparison support as a second artifact referenced via metadata). `unavailable_dimensions` lists requested dimensions without data: `THERMAL` (no thermal source) ⇒ `NO_COVERAGE`; `SCIENCE`/mineral ⇒ `NO_COVERAGE`. `BLOCKED` when the AOI misses the dataset (`NO_COVERAGE`), CRS/frame unresolved (`UNSUPPORTED_CRS`), or `valid_fraction < 0.05`.

### 4.5 `SCREEN_CANDIDATES`
Generate the deterministic window grid (architecture 36 §6 / `candidates.yaml` `practice-earth-grid-v1`), compute per-window coarse summaries from the Earth source (valid land fraction, `slope_area_fraction` for **every band named in the requirements' `parameters.slope_band_deg`**, W1 to the target histogram at the common support), exclude `WATER_ONLY` (≥ 0.98 water), `INSUFFICIENT_VALID_DATA` (valid land fraction < `min_valid_fraction`), rank the rest by `(deficit asc, w1 asc, window_id)`, take the top `max_detailed − (negative controls)` plus the labeled negative control(s) (windows whose `candidates.yaml` entry has `negative_control: true` **and** that rank within the ranked set), record `BELOW_SHORTLIST_CUTOFF` for the rest, tag origins from `reference_set_id` (`KNOWN_ANALOG`/`KNOWN_CONTROL`, `SYNTHETIC_CONTROL`, else `DISCOVERED`/`NOT_IN_REFERENCE_LIST`). `feature_scores` are mission deficits only. Output the complete `ScreenCandidatesPayload` incl. `stop_reason`, `search_extent`, limitations (e.g. "bounded search; no global-optimality claim"). One `DERIVED` evidence per non-excluded window (metrics above) plus one screening evidence (artifact JSON of the whole table). The expected result for the practice grid is exactly architecture 40 §4.1.

### 4.6 `ANALYZE_CANDIDATE`
Read the window at the analysis cell size (60 m; **derivatives are computed over the whole source extent first and then cropped to the window**, so a window's 3×3 halo is real data and only cells at the outer source boundary or adjacent to nodata/water are invalid; aggregate by area averaging if the source is finer; **never** upsample — a coarser source stays coarse and `support_scale_m` says so), build the ANALYSIS_GRID (valid/land masks, slope, quality), histogram, roughness/relief at 3/5/9-cell windows, connected safe zones (`slope ≤` the **largest rover/contract cap known: 18°** by default from `thresholds.default_cap_deg`, valid, land) with per-zone band areas, optional mineral valid fraction (nearest/area-fraction, never interpolating ids). Evidence: `DERIVED` analysis (artifact = the ANALYSIS_GRID, role `ANALYSIS_GRID`) ← parents source/screening. `LIMITED` when coverage < `min_valid_fraction` but ≥ 0.05, `BLOCKED` below 0.05 or on CRS problems.

### 4.7 `COMPARE_REQUIREMENT`
Dispatch on `observable_policy_id` (from `catalog.OBSERVABLE_POLICY_BY_OBSERVABLE`); an unknown observable ⇒ `UNKNOWN / REQUIREMENT_UNDERSPECIFIED`. Common gate order (architecture 11 §2): (1) physical-gap check (`operator == NOT_NATURALLY_REPRODUCIBLE` ⇒ `GAP / PHYSICAL_GAP`); (2) evidence adequacy: body/units/frame, support scale against `[minimum_support_scale_m, maximum_support_scale_m]` (a requirement window that excludes the available support ⇒ `UNKNOWN / SCALE_UNSUPPORTED`), coverage vs `min_valid_fraction` (⇒ `UNKNOWN / INSUFFICIENT_VALID_DATA`), mode consistency; (3) the policy's numeric rule; (4) confidence per the rubric: `MEDIUM` for direct terrain-model evidence with coverage ≥ 0.9 and unquantified-but-accepted nominal uncertainty, `LOW` if coverage < 0.9, never `HIGH` without quantified uncertainty, never `UNASSESSED`. Policy rules (all thresholds inclusive):

| policy id | rule |
| --- | --- |
| `slope-band-area-fraction-v1` | measured `slope_area_fraction:<band>`; PASS iff ≥ `lower` else FAIL `INSUFFICIENT_EXPOSURE` |
| `slope-w1-common-support-v1` | recompute W1 at the common support; PASS iff ≤ `upper` else FAIL `DISTRIBUTION_MISMATCH`; target evidence missing ⇒ `UNKNOWN / TARGET_EVIDENCE_MISSING` |
| `route-exposure-v1` / `route-tasks-v1` / `route-reserve-v1` | no `verification` supplied ⇒ `UNKNOWN / ROUTE_NOT_VERIFIED`, `PRELIMINARY`; with verification: take the matching benchmark/metric — PASS ⇒ `PASS / ROUTE_VERIFIED`, FAIL ⇒ `FAIL / ROUTE_FAILED` (or `FAIL / INSUFFICIENT_EXPOSURE` when named by an infeasible diagnosis), energy unevaluable ⇒ `UNKNOWN / ENERGY_MODEL_MISSING`; always `FINAL` once verification is supplied; the verification evidence handle must be among `candidate_evidence_ids` |
| `mineral-presence-v1` | Earth mineral evidence absent ⇒ `UNKNOWN / EARTH_EVIDENCE_MISSING`; else target mineral evidence absent ⇒ `UNKNOWN / TARGET_EVIDENCE_MISSING`; both present ⇒ `UNKNOWN / THRESHOLD_UNRESOLVED` (no accepted proxy rule exists) |
| `thermal-min-v1` | Earth thermal evidence never exists in v1 ⇒ `UNKNOWN / EARTH_EVIDENCE_MISSING` even when the target has a thermal metric |
| `clearance-scale-v1` | support > requirement `maximum_support_scale_m` ⇒ `UNKNOWN / SCALE_UNSUPPORTED` |
| `physical-gap-v1` | `GAP / PHYSICAL_GAP` |

Output `CompareRequirementPayload` incl. `adequacy: AdequacyReceipt` (gates SC-02…SC-11, SC-13 per architecture 33; `NOT_APPLICABLE` only with an observable-specific reason; SC-08 for nominal terrain-model results is `SATISFIED` with the limitation "uncertainty not quantified; nominal modeled result"). Evidence: `COMPARISON`.

### 4.8 `ASSESS_COMPATIBILITY`
Dimensions (`metric_id`): `max_surface_slope_deg` (PASS iff `rover.max_slope_deg ≥` the highest `slope_band_deg` upper in the requirements; FAIL otherwise — `PRACTICE-LITE` ⇒ FAIL), `energy_reserve_pct` (UNKNOWN while `preliminary`; with verification: PASS/FAIL from the verifier's reserve; UNKNOWN when `energy_model` null), `ground_clearance_m` (UNKNOWN when any `field_validation` clearance requirement exists and support is coarser than its window), `max_obstacle_height_m` (UNKNOWN when null), `required_capability:<capability>` (PASS "declared, not observed" if listed; UNKNOWN if the profile lists no capabilities field value), `route_length_m` (vs `max_route_m` when non-null). Never infer clearance/obstacle capability from wheel diameter. `preliminary = (no verified route supplied)`.

### 4.9 `DESIGN_BENCHMARK`
Build a `ConstraintsArtifact` from the frozen mission+rover+candidate. Raster candidates: `grid` from the candidate's analysis evidence; start/tasks by **`auto-waypoints-v1`** (architecture 40 §6) on the candidate grid under the effective cap = `rover.max_slope_deg`; exposures from every `unique_slope_exposure_m` requirement (`ExposureSpec.upper_inclusive` = true iff the band upper equals the rover cap); `max_distance_m` = `rover.max_route_m` or `design_defaults.max_route_m`; energy from `rover.energy_model` (or `None`); `blocked_edge_ids` from the input (RECOVERY); `strategy` as requested. Graph scenario (`graph_fixture_id="canonical-graph-v1"`): `artifact_kind=SYNTHETIC_GRAPH_REGRESSION`, graph and constraints from the fixture, mock energies, `resource_provider=TEST_ONLY_MOCK_GRAPH`, **only when `mode=="synthetic"`** (else `BLOCKED`, `INPUT_INVALID`). Map every accepted requirement in `requirement_mapping` (route-verifiable ⇒ `VERIFIED_BY_TOOL`; clearance/mineral ⇒ `UNKNOWN`; gaps ⇒ `GAP`; capability-only ⇒ `DECLARED_ONLY`). `blockers`: rover cap < band lower ⇒ a blocker issue `ROVER` conflict is *not* raised here (let search/diagnosis prove it); a missing mandatory input (no grid evidence) ⇒ `BLOCKED`. Never lower a threshold. Artifact `CONSTRAINTS` (JSON; `constraints_sha256 = canonical_sha256(artifact)`).

### 4.10 `SEARCH_ROUTE`
Preconditions: constraints valid (a `None` energy model means **no energy pruning or bound** is applied; energy-dependent outcomes are then left to the verifier as `ENERGY_UNCALIBRATED`); `constraints_sha256` equals the recomputed canonical hash (else `BLOCKED` `STALE_INPUT_HASH`). Procedure (architecture 12 §6, as specified here):
1. Build the directed graph (raster: 8-neighbour on valid land cells with slope ≤ cap, after dilation by `footprint_dilation_m`; edge crossing allowed only if every intersected cell is valid, land, slope ≤ cap, not blocked; edge hazard slope = max cell slope by **DDA/Amanatides–Woo** traversal; abstract graph: given). Edge costs: `d_xy`, `dz`, `d_s`, nominal/conservative energy (physical model, or mock energy for the graph fixture).
2. **Certificate step.** Compute the start component; verify all tasks and the start are connected (else `EXHAUSTIVE_INFEASIBLE`, certificate "task unreachable"); optimistic exposure bound per requirement = `min(sum of band-subsegment lengths over the component's undirected edges, max_distance_m, usable_energy_bound)`; any bound `< minimum_distance_m` ⇒ **lossless** `EXHAUSTIVE_INFEASIBLE` with `labels_pruned_lossy = 0` (strategy `WAYPOINT_RETURN` skips exposure bounds). Energy bound: minimum possible energy of any closed route visiting all tasks (shortest-path lower bound) `>` usable energy ⇒ lossless infeasible.
3. **Best-first label search** ordered by `(distance_m, energy_conservative_wh, node_sequence)`; label = node, task bitmask, covered unique `(edge, cell)` exposure set **saturated at each requirement's minimum** (stop tracking once met), edge traversal counts, energy, time, distance, predecessor. Dominance only between labels with identical (node, task mask, relevant exposure/traversal state) as architecture 12 §6. Keep ≤ `max_labels_per_node` non-dominated labels per node **per equivalence class**; truncation ⇒ increment `labels_pruned_lossy` and set `approximation_flags`.
4. Expand allowed edges (traversals ≤ 2 per undirected edge); complete tasks on arrival; a label is a **solution** when at the start with all tasks done, closure satisfied and (strategy ≠ `WAYPOINT_RETURN`) exposures saturated. The first popped solution is the minimum-distance route within the bounded domain; stop.
5. Termination: solution ⇒ `FOUND`; queue empty with `labels_pruned_lossy == 0` ⇒ `EXHAUSTIVE_INFEASIBLE`; budget (expansions/seconds) or lossy pruning ⇒ `BUDGET_EXHAUSTED`; engine error ⇒ `ERROR`.
Output `SearchRoutePayload` (route artifact `ROUTE`, counters, `optimistic_exposure_bound_m`, `termination_reason`). The route stores `solver_claimed` totals — **informational only**. Strategy semantics: `WAYPOINT_RETURN` ignores exposures in the search (verifier decides); `EXPOSURE_COVERAGE`/`MINIMUM_FEASIBLE_ROUTE`/`RECOVERY_ALTERNATIVE` require exposure saturation.

### 4.11 `VERIFY_ROUTE`
**Independent.** Reload the grid/graph and constraints (not the searcher's graph objects). Recompute from `route.node_sequence` alone: continuity (each consecutive pair is an allowed adjacency), per-edge cell intersection lengths by **slab clipping** (a different algorithm than the solver's DDA), hazard/forbidden/unknown intersections, max slope, edge traversal counts, tasks reached/dwell/capability, return closure within tolerance, distance, duration, unique exposure per requirement (`UNIQUE_UNDIRECTED_EDGE_DISTANCE` vs `TOTAL_TRAVERSED_DISTANCE`) with band rules, energy nominal/conservative/reserve (physical model with Earth gravity `9.80665`, or mock provider for the graph fixture), per-constraint `BenchmarkRow`s (`constraint_id` per `catalog` naming, margin sign convention in the model), `RouteViolation`s with codes from the kit, telemetry per node. Outcome rule: any definite mandatory violation ⇒ `FAIL` (category `ROUTE`; `ROVER` only if the violated constraint derives from a rover limit **and** `DIAGNOSE_RESULT` supports it — verification itself reports `ROUTE`); else any required-but-unevaluable item (missing energy model ⇒ `ENERGY_UNCALIBRATED`) ⇒ `INCONCLUSIVE` with `DATA`; else `PASS` with `verified_route_sha256`. Reject: stale constraints hash (`STALE_INPUT_HASH` violation ⇒ `INCONCLUSIVE/SYSTEM`), non-adjacent steps (`DISCONTINUOUS_ROUTE`), falsified `solver_claimed` (informational — the verifier simply ignores it, and a test shows verifier output ≠ claimed). Evidence `VERIFICATION` (parents: input evidence) + `TELEMETRY` artifact (`TelemetryArtifact`; `reserve_pct` may be negative; null for unknown).

### 4.12 `DIAGNOSE_RESULT`
Apply the failure-to-action policy of architecture 12 §8 / role 09: ROUTE ⇒ permitted `NEW_ROUTE` with the recommended strategy `EXPOSURE_COVERAGE` when the failed strategy was `WAYPOINT_RETURN` and that strategy is untried in `attempt_history` for this candidate; if no untried strategy remains ⇒ `NEW_CANDIDATE` when `remaining_candidate_switches > 0`, else `permitted_repairs=[]` (`NEW_ZONE` is not produced in v1); `EXHAUSTIVE_INFEASIBLE` ⇒ apply the **ANALOG vs ROVER rule** of architecture 40 §6 by re-running the certificate with rover-dependent constraints removed (slope cap→90°, battery unbounded) but all terrain masks kept: feasible ⇒ `ROVER` with `permitted_repairs=[NEW_CONTRACT_REQUIRED]` only (the rover limit is the binding cause, so another candidate cannot cure it); infeasible ⇒ `ANALOG` with `NEW_CANDIDATE` (if switches remain) else `COMPOSITE_PORTFOLIO`; `BUDGET_EXHAUSTED` ⇒ `SEARCH_LIMIT`, `NEW_ROUTE` with a *different registered strategy* if one is untried, else none; missing energy model ⇒ `DATA`, `[DATA_REPAIR]`; never `NEW_CONTRACT_REQUIRED` as an automatic action — it only appears as a permitted-but-requires-new-run option. `proof_scope` text names the exact scope ("evaluated route only", "discrete graph of this zone under frozen constraints", "domain-bounded certificate"). Repairs are limited by `remaining_route_repairs` and `remaining_candidate_switches`; zero remaining ⇒ `permitted_repairs=[]` and the platform stops.

### 4.13 `OPTIMIZE_PORTFOLIO`
Exhaustive subset enumeration (≤ 12 eligible candidates; reject more with `RESOURCE_LIMIT`), coupled groups by `co_location_group` evaluated as joint items using `verification_by_window_id` (a coupled item is covered by a site only when that site's verification outcome is `PASS` **and** all member rows are PASS/FINAL), lexicographic objective of architecture 13 §3, deterministic ties by sorted `window_id`. Eligible coverage requires `PASS`, `FINAL` stage for route-dependent rows, no blocking critic issue. Residuals list UNKNOWN/GAP/NONE requirement ids. Output `OptimizePortfolioPayload` (empty selection allowed). Passes all seven fixtures of architecture 13 §6.

### 4.14 `BUILD_DISPLAY_LAYERS`
For each requested layer kind produce a PNG (`DISPLAY_IMAGE`) + `DisplayLayerDraft`: Earth ⇒ Web-Mercator-rendered image with four WGS84 `earth_corners` in **NW,NE,SE,SW** order; Moon/Mars ⇒ planar image with the body-specific GDAL-order `pixel_to_world` and `display_crs_wkt`, `earth_corners=None`. Colormap + `legend` with units, `nodata_transparent` (alpha 0 for invalid), `support_scale_m`, `attribution` (synthetic ⇒ "SYNTHETIC PRACTICE DATA — not terrain of this location"; real ⇒ from the manifest `citation`/`license_note`), limitations ("display smoothing adds no resolution"). The image is a display artifact only; no later operation consumes it. Control-point tests: the four corners and one interior point round-trip through the affine within 0.5 pixel.

### 4.15 `AUDIT_EVIDENCE`
