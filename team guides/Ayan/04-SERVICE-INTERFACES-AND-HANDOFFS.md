# Ayan interfaces and handoffs

Your deliverable is a scientific service Tanush can call and Aradhya can inspect. Shared03 defines the exact boundary; F0 turns it into typed Python ports. Do not substitute a notebook screenshot, standalone map app or loosely named JSON file.

## Inputs from Tanush

Frozen accepted contract/optional saved rover values, operation-specific materialized inputs, authorized existing evidence/array handles, source policy, current mode, algorithm settings, resource budget, cancellation/deadline/progress interfaces and safe scratch/download context. Requests carry enough actual values to compute; a database UUID alone is not enough for a pure science function.

For source acquisition obtain only approved selection identities/hosts and the documented adapter credential path. No environment scan or arbitrary model-selected URL. A live request cannot enable the test-only graph energy provider. A synthetic request cannot use a hidden live-source/model fallback.

## Outputs to Tanush

Return ScienceComputationResult with operation/status, algorithm/input/parameter hashes, typed payload, issues and local artifact/evidence drafts. Include body/frame/longitude/vertical reference/native/comparison support, valid fractions, masks and limitations. Temporary handles must stay inside provided scratch roots. Parent local keys refer to drafts in this result; existing evidence IDs refer to actual authorized persisted evidence.

Tanush verifies/moves/registers/allocates UUIDs and supplies the real public entities/receipts. You must give a complete deterministic metric/predicate/result rather than asking a model to infer PASS from a chart. Qualification status is a proposal until platform policy commits; independent verifier outcome is computed and cannot be overwritten by the role explanation.

Each operation needs a stable typed sample request/result and at least one missing-data/rejection example. Operation names and public tool mapping are in shared03. If a new scientific parameter changes accepted requirements, request a contract revision rather than hiding it in algorithm options.

## Outputs to Aradhya

Provide a small registered display fixture through Tanush: DisplayLayerManifest plus image bytes/legend, Earth corners or planetary affine/CRS, source support, actual nodata transparency and attribution. Also provide route geometry/telemetry and metric units/class definitions so UI labels are exact. Do not ask frontend to parse PDS/NetCDF or recompute energy. Display images are not analytical evidence arrays.

Explain physical limitations in concise field-specific text: unresolved clearance, user-designated sample access, unconfirmed mineral match, regional target context, modeled energy assumptions, search bounds. These captions must survive passport export, not disappear after a green terrain badge.

## Checkpoint handoff

S0: analytic math/graph, typed facade and tests, expected result arithmetic, dependency requests and tested SHA. S1: actual supported source adapters/discovery/portfolio/display, source lock/asset report, validation controls, performance/resource data and blockers. Report corrected decoders/scale changes that invalidate earlier derivations.

If a port is incompatible, submit an exact change request in your handoff directory with before/after fields and affected tests; Tanush owns shared schema/lock changes. Keep working on independent science while it is resolved. Do not make unreviewed edits in platform paths or silently ship an adapter the registrar cannot consume.

## C1 scientific assurance seam

Follow your [scientific credibility implementation requirements](07-SCIENTIFIC-CREDIBILITY-REQUIREMENTS.md) and [shared gate06](../../team%20coordination/06-SCIENTIFIC-CREDIBILITY-AND-RELEASE-GATE.md). Include actual SC gate/SCI test evidence, policy/algorithm/source hashes, validated claim scope and visible unknowns in your checkpoint. The required C1 audit must cross the real science→backend→UI/export boundary before combined acceptance. Missing/unrun external validation remains explicit; it cannot be called passed.
